# What is documented here

This reference is curated, not generated by walking the package. A module
appears here by deliberate addition, because its surface is people-facing:
something a caller types at a call site. Private helpers, and internals
whose docstrings are written for maintainers, stay in the source.

Two deliberate omissions, and where to read them instead:

**`dimma.accounting`.** Its functions are people-facing —
`poisson_gaussian_epsilon` appears on the
[getting started](../getting-started.md) page — but their docstrings are
written as part of the repository's internal decision record, and this
site [explains those decisions in its own voice](../library/map.md)
instead. Read the accounting docstrings in the source:
[`src/dimma/accounting/`](https://github.com/Larraguibel/dimma_lib/tree/main/src/dimma/accounting).
Every function there states the mechanism it assumes; that statement is
the contract.

**The non-classical algorithm packages.** Each package's `__init__`
docstring tabulates its paper's notation, symbol by symbol, against the
code that implements it — the single most useful piece of documentation
for reading that algorithm, and best read next to the code it maps:
[`src/dimma/algorithms/`](https://github.com/Larraguibel/dimma_lib/tree/main/src/dimma/algorithms).
The prose story of each algorithm is on its
[own page](../algorithms/index.md) here.

What renders on the following pages:

- [Core stages](core.md) — the pipeline primitives in `dimma.core`.
- [Algorithms](algorithms.md) — classical DP-SGD's `train` and `step`.
- [Transforms](transforms.md) — the projection wrappers.
- [Data, models, and metrics](evaluation-stack.md) — the reference
  model, its losses, and the evaluation stack.
